# Chrome Sync 使用与验证

1.4.0 接入 `chrome.storage.sync`。安装仍然只需直接加载 `extension` 文件夹，固定 ID 保持 `fhohijfjoehgofnnnghbgiglmaagemni`。

## 开始使用

1. 两台设备的 Chrome 登录同一 Google 账号，并在 Chrome 同步设置中启用扩展相关数据同步。仅登录 Gmail 或安装同一扩展并不等于 Chrome 同步已打开。
2. 在第一台已有完整快捷方式的设备上更新并刷新扩展，重新打开新标签页，进入「自定义 More Slots → Chrome 同步 → 启用同步」。
3. 在另一台设备安装同一版本，也点击「启用同步」。若本机仍是初始六个示例网站，会使用已有的 Chrome 同步配置。
4. 如果两边各有自定义配置，会显示数量并提供「合并两份配置」「使用 Chrome 中的配置」「用本机替换 Chrome 中的配置」。合并保留 Chrome 中的顺序和设置，同网址保留 Chrome 中的条目，本机独有网站追加到末尾。
5. 在第一台新增一个临时快捷方式，在另一台点击「立即同步」或重新打开新标签页，确认新增能到达；再删除它，确认删除也到达。Chrome 的实际网络传播不是即时保证的。

无需额外 Google Drive 授权或自建服务器。每台设备独立选择是否启用本功能；关闭一台设备的同步不会关闭其他设备，也不会清空 Chrome 中的数据。

## 同步范围

- 同步：快捷方式名称、网址、排序，以及数量、列数、主题、打开方式等设置。
- 本机保留：favicon 图标缓存、搜索历史、书签读取授权、启用同步的开关及启用前快照。
- 原生书签由 Chrome 自己的书签同步负责，本扩展只读取展示，不把书签复制到扩展同步存储。

本机始终保留配置，离线状态继续可用。启用前自动保存一份本机快照，可在设置里「下载启用同步前的备份」后通过原有导入功能恢复。

## 状态的含义

「已提交给 Chrome 同步」表示扩展已成功写入 `chrome.storage.sync`，**不代表 Google 已上传完成或另一台设备已经收到**。Chrome 未登录、同步关闭或网络不可用时，该 API 仍可能只在本机保存；本扩展没有读取账号或 Chrome 私有同步诊断信息的权限。

因此应同时检查两端的 Chrome 同步设置，并通过一次新增/删除测试验证实际跨设备传播。设置里提供 Chrome 同步设置入口、立即同步、最近提交时间、占用空间和错误提示。

## 冲突与限额

网站分别保存为同步记录；删除保留带版本的删除标记，阻止落后的设备重新带回旧记录。独立新增能够合并；同一网站或整组设置同时修改时，按单调递增逻辑时间及设备标识确定胜者。排序冲突会得到一致结果，可能需要用户按最终意图再拖动一次。

Chrome Sync 总容量约 100 KB，单项约 8 KB，最多 512 个键。本实现每个网站一个键、设置一个键，删除标记也占键数及容量。因此本机支持 1000 个快捷方式不等于全部都可以同步。超限或写入失败会保留本机数据，显示错误，并通过后台重试。首次尚未成功同步的项目被删除后，会移除无用的删除标记，允许缩小列表后重试。

后台 Service Worker 负责串行处理保存和同步，短延迟合并提交；定时唤醒负责后台被回收后的重试。不会把搜索记录、图标或私钥放入 Chrome Sync。

## 测试边界

自动测试覆盖了首次加入、合并和替换、并发新增、删除防复活、排序和设置、关闭/重启、写入失败重试及配额保护。

浏览器集成测试使用独立 Chromium 资料，调用真实 Chrome 扩展存储 API，并复制两端 `storage.sync` 数据来模拟 Google 的传播，验证后台、页面接收、服务工作线程重启及设置交互。它不等价于已登录 Google 的真实 Mac/Windows 跨设备同步；后者需要在实际设备上完成上述新增/删除验证。

官方依据：[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。
